# Clean-HyperVOrphans

**简体中文** | [English](README.en.md)

清理 Hyper-V 管理器删除虚拟机后**残留在磁盘上的 VHDX / AVHDX 文件**。

> **「孤儿」是什么意思**
> 借的是 orphaned object 这个说法：文件还在磁盘上，但当前已注册的任何虚拟机（含快照链、父盘）都不再引用它。
> 它**只表示「没人引用」，不表示「没有价值」**。基线盘、模板盘、留着以后挂载的备份盘，放在 Hyper-V 目录里同样会被判定成孤儿。工具负责把它们列出来，删不删由你看路径决定。

## 它解决什么问题

在 Hyper-V 管理器里删除虚拟机时，会有一个选项：**「删除虚拟机的虚拟硬盘文件」**。

- 没勾选它 → 虚拟机的配置删了，但 `.vhdx` 文件原封不动躺在磁盘上，继续占几十 GB
- 干脆没注意到这个选项 → 同上，而且事后很难想起来是哪台机器留下的
- 删掉的虚拟机带着检查点 → 整条磁盘链（`.vhdx` + 各级 `.avhdx`）一起变成无引用文件，一串几十上百 GB
- 检查点合并（Merge）中途失败或被取消 → 会留下差值盘，但这时它**通常仍被虚拟机引用**，不一定进得了本清单，别指望靠这个工具收尾

这些文件在 Hyper-V 管理器里**没有任何入口**——没有对应的虚拟机，就点不到它的磁盘。在资源管理器里当然看得见，可你没法一眼分清哪个能删、哪个还是某台机器的父盘。磁盘空间就这么被吃掉，而你在「磁盘使用情况」里只能看到 Hyper-V 目录莫名很大。

这个工具的作用：扫描 Hyper-V 的磁盘目录，把它们和当前所有虚拟机（含快照、父盘链）实际引用的路径逐一比对，**找出没有被任何虚拟机引用的文件**，交给你确认后删除。

> **⚠️ 扫描范围是有限的，先确认你的硬盘建在哪**
> 默认只扫三处：`Get-VMHost` 里配置的虚拟硬盘路径、`C:\ProgramData\Microsoft\Windows\Hyper-V`、`C:\Users\Public\Documents\Hyper-V\Virtual Hard Disks`。
> 如果磁盘建在别处（`D:\VMs`、`E:\HyperV`、群集共享卷、自建的存储池目录……），**必须在启动时手动输入那个路径**（多个用逗号分隔），否则那些目录压根不会被扫到——清单一律为空，且空清单**不代表**磁盘上没有残留。

## 为什么不能直接在资源管理器里手工删

两个坑，都会真的踩到：

**一、正在使用的磁盘长得和孤儿盘一模一样。** 凭文件名、大小、修改时间都分不出来。本工具通过 `Get-VM` → `Get-VMHardDiskDrive`（含快照挂载）+ `Get-VHD` 的 `ParentPath`（父盘链）收集全部在用路径，做精确匹配后才排除。Hyper-V 模块缺失时会要求输入 `CONTINUE` 才继续，不会盲扫。

**二、`RecycleOption.SendToRecycleBin` 在文件超配额时会静默永久删除。** 这是本工具存在的主要理由，详见下一节。

## 核心：回收站配额预检

Windows 的回收站 API（`Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile` + `SendToRecycleBin`）底层走 `SHFileOperation` + `FOF_ALLOWUNDO`，行为是这样的：

> **只有「放得进回收站」时才走回收站。文件体积超过该卷回收站容量上限时，Shell 会直接永久删除。**

正常 GUI 操作会弹「文件太大，无法放入回收站，是否永久删除？」。但脚本传 `UIOption.OnlyErrorDialogs` 会把这个提示一起抑制掉——于是变成**静默永久删除**，你以为进了回收站，其实已经没了。VHDX 动辄几十 GB，而回收站上限通常只有几 GB，所以这是**必然触发，不是偶发**。

因此删之前必须先算，本工具的做法：

**上限从哪来**

1. 优先读当前用户的自定义配额：`HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\BitBucket\Volume\{卷GUID}\MaxCapacity`
2. 没有自定义值时，按 Windows 默认规则推算：

   ```
   上限 = min(卷容量, 40GB) × 10% + 超出 40GB 的部分 × 5%
   ```

   这个公式用真实机器数据反向验证过，5 个卷的误差均 < 0.15%。

**分三档**

| 分级 | 判定 | 后果 | 确认词 |
|---|---|---|---|
| 直接回收 | 剩余空间够，不挤占任何旧条目 | 可随时从回收站还原 | `YES` |
| 挤占回收 | 单文件不超上限，但空间不够 | 会静默挤掉回收站里最旧的条目，并预告挤掉多少 | `YES` |
| 永久删除 | 单文件超过该卷回收站上限 | **无法还原** | `NUKE` |

只输入 `YES` 时，第三档的文件一个都不会动。两档确认互相独立，不存在「一个 YES 全删」的路径。

**删完复核**

不信 API 的返回值，只看回收站里有没有真的多出那个文件：对比该卷 `$Recycle.Bin` 删除前后的文件表，找新增的 `$R*` 且大小等于原文件。找不到就明确告警「文件已消失但回收站里没有，等于永久删除」。

> 实测过一个问题：删除 API 会抛「无法找到指定文件」，但文件其实删成功了，异常是 Shell 收尾时的误报。所以成败判定只能回查目录，不能看异常。

## 工作流程

```
[0/5] 运行环境自检      管理员权限？Hyper-V 模块？
[1/5] 收集在用磁盘      VM 硬盘 + 快照链 + Get-VHD 父盘
[2/5] 确定扫描目录      VMHost 默认路径 + ProgramData + Public，可追加
[3/5] 扫描比对          *.vhdx / *.avhdx 中排除在用路径 → 孤儿清单
[4/5] 展示清单          序号 / 风险 / 类型 / 大小 / 盘符 / 最后写入 / 路径
[5/5] 回收站配额预检    逐文件分档 → YES / NUKE 两道确认 → 删除 → 复核
```

风险标记只有两种：`[安全]`（`.vhdx`，未匹配到任何 VM 引用）、`[谨慎]`（`.avhdx`，孤立差分盘或存在父盘，可能残留未合并的差异数据）。`[安全]` 说的是「没有引用关系」，不是「确认没用」——路径还是得自己看一眼。

## 快速开始

### 方式一：直接运行脚本

需要管理员权限（读取回收站占用、调用 Hyper-V cmdlet）。

```powershell
# 在管理员 PowerShell 中
powershell -NoProfile -ExecutionPolicy Bypass -File .\Clean-HyperVOrphans.ps1
```

### 方式二：编译成 exe（推荐，双击即用）

需要 `ps2exe` 模块：

```powershell
Install-Module ps2exe -Scope CurrentUser
```

然后：

```powershell
.\build.ps1
```

生成的 exe 内嵌 `requireAdministrator` 清单，**双击自动弹 UAC**，不需要右键「以管理员身份运行」。窗口固定 120×40、缓冲区 3000 行、屏幕居中。

> 首次启动会多花几百毫秒，因为要用 `Add-Type` 现场编译一小段 Win32 互操作代码来居中窗口。失败时静默跳过，尺寸和缓冲照样生效，不影响主流程。
>
> 如果 `Install-Module` 报 405 或网络受限：`ps2exe.<版本>.nupkg` 本质就是个 zip，下载后解压，把内容放到 `%USERPROFILE%\Documents\WindowsPowerShell\Modules\ps2exe\<版本>\`，再 `Import-Module ps2exe` 即可。

## 已知限制

- **只认 `.vhdx` / `.avhdx`**：老式 `.vhd` 格式（以及 Hyper-V 2012 R2 更早版本的 `.avhd`）不在扫描范围内，得手工处理。清单为空不代表磁盘上真的没有残留。
- **只清磁盘文件，不清配置残留**：删掉的虚拟机还会留下 `Virtual Machines\<GUID>.xml`、`Snapshots\`、`Smart Paging\` 等目录，本工具不碰。
- **路径按字符串精确比对**（大小写不敏感）：磁盘若被以 8.3 短名（`PROGRA~1`）、符号链接、`subst` 或挂载点方式引用，可能匹配不上而被误判成孤儿。清单里出现「看着像还在用」的文件，先核对再动手。
- **已挂载到宿主机的 VHDX 删不掉**：若文件正被 `Mount-VHD` 挂载，删除会失败并提示「文件仍存在，可能被 vmms 占用」。
- **非管理员运行**：读不到回收站已占用量，只能按文件大小判断（会明确警告），并跳过「删完复核回收站」这一步——否则读不全 `$Recycle.Bin` 会误报成永久删除。
- **未安装 Hyper-V 模块**：无法识别正在使用的磁盘，必须输入 `CONTINUE` 才继续。这种模式下使用等于盲删，不建议。
- **网络路径 / U 盘 / 无 `$Recycle.Bin` 的卷 / 该卷回收站被设为直接删除**：一律划进「永久删除」档，强制 `NUKE`。
- **Windows Terminal 下部分外观设置不生效**：脚本内的窗口尺寸/居中针对传统 conhost 编写。若默认终端是 Windows Terminal，字体与配色由 WT profile 接管。
- **回收站已满的盘**：即便单文件不超上限，也会走「挤占回收」，静默挤掉最旧的条目。想保住里面的东西，先把回收站调大或清空。

## 想让大 VHDX 也能进回收站

唯一的办法是调大对应卷的回收站上限：右键回收站 → 属性 → 选中该盘 → 自定义大小，调到 ≥ 最大的单个文件体积。调完再跑本工具，原本「永久删除」档的文件就会变成「直接回收」档。

## 免责

这是个**会删除文件**的工具。虽然有三层保护（在用路径排除、配额预检、删后复核），但：

- 第一次使用时，**建议先只选 1 个文件**，确认回收站里真的出现了它，再批量处理
- 确认删除前，务必核对清单里的路径是不是你想要的那个

使用本工具即表示你理解上述风险并自行承担后果。
